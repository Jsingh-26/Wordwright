# Build plan

Target: **v1.0 of a snippets-only Wordwright on the Microsoft Store** — a text expander, nothing else. Phases P0–P3 are done, P3.6 (the Store package) is done, and P10 (release) is what remains.

> **The AI writing assistant is parked, not deleted.** Wordwright was also built with an on-device AI rewriting feature. It was implemented, released three times (v0.1.3–v0.1.5) and made to work, but it could not be tested on real hardware, so it is not part of the shipping application. Everything about it — the plan, how it was built, what was proven, what never was, and how to resume — is in [`AI_REWRITING.md`](AI_REWRITING.md), and the code is on the `ai-rewriting` branch.
>
> The phase sections below are kept as the historical record. **P4–P9 are parked**: they describe work that is not in this application. `main` carries no AI code.

### Blockers (the app misbehaves for a real class of users)

- [x] **P12.1 Keyboard hook ignores Shift, Caps Lock and AltGr.** `KeyboardHook.Translate` calls `GetKeyboardState` on the worker thread, which has no input queue, so the state it passes to `ToUnicodeEx` never has a modifier set. Measured with a probe against `Wordwright.Platform` (`scripts/HookProbe`, added by this review): Shift+S arrived as `s` while the target text box received `S`; Shift+1 arrived as `1` (target: `!`); Caps Lock + s arrived as `s` (target: `S`). Consequences: any prefix that needs Shift (`:`, `#`, `!`, `@`, `$`) never expands; on German, Spanish, Italian, Nordic and most other European layouts `;` itself is Shift+`,`, so **the default prefix is dead for those users**; case-sensitive triggers are a fiction (typing `;Sig` expands the `sig` snippet); `!` or `?` after an ambiguous trigger arrive as `1` or `/`.

### Decisions needed (v1.1 candidates; each is a product choice for the maintainer)

Ordered by how much they would set Wordwright apart, against what they cost. The niche study in DESIGN.md found three things nobody in the category does on Windows: private and offline with no account, no caps, and a first run you can try inside the app. The candidates below extend that list rather than chase feature parity.

- [ ] **D14 Snippet picker hotkey (no AI).** When the palette was parked (P6.8), the only way to insert a snippet whose shortcut you forgot went with it; every competitor has a picker. A small floating list near the caret (Fluent flyout, 360 px, DESIGN §6 minus the AI rows), opened by one global hotkey (default Ctrl+Shift+Space; recorder row in Settings), filter by name or shortcut, Enter inserts through the normal paste path, Esc leaves the text untouched. The palette shell, `HotkeyService` and the hotkey recorder already exist on the `ai-rewriting` tag and need only the AI rows removed. **Cost:** medium. **Needs copy:** palette placeholder, Settings row, the in-use hotkey error (all exist in UX_COPY's parked sections).
- [ ] **D15 Backspace undoes an expansion.** Pressing Backspace within two seconds of an expansion removes the inserted text and types the shortcut back, so a wrong expansion costs one key instead of a careful delete. Espanso has it; none of the Windows GUI expanders do it well. Needs `InputSender.TypeText` (`KEYEVENTF_UNICODE`) and a short-lived "last expansion" record in `SnippetEngine` (length and shortcut, in memory, cleared after two seconds or any other key). **Cost:** low. **Needs copy:** none.
- [ ] **D16 Shortcut case carries into the text.** Now that the hook sees Shift (P12.1), `;Sig` could insert the body with its first letter capitalised and `;SIG` the body in capitals, while `;sig` stays as written. Opt-in per snippet ("Match the case I type") or one global setting. Core-only logic (`CaseShaper`, tested) plus the toggle. Espanso calls this propagate case; no Windows expander in the study offers it. **Cost:** low. **Needs copy:** one row.
- [ ] **D17 A prefix that fits the keyboard.** With P12.1 the `;` prefix works on a German layout, but it still needs Shift there. At first run, if `VkKeyScanEx(';')` on the active layout needs Shift, the welcome window could say so and offer an unshifted alternative for that layout (`#` on German, `,` is too common in prose, `/` needs Shift on QWERTZ), with the Settings row to change it later. A detail no competitor gets right. **Cost:** low. **Needs copy:** one welcome line and the prefix row text.
- [ ] **D18 Import from other expanders.** Settings → Import today reads only Wordwright's own JSON. Reading a CSV/TSV (`shortcut, name, text`), an Espanso `match` YAML and a Beeftext JSON export turns "switching" into one click, which is exactly what people searching "Text Blaze alternative Windows offline" (LAUNCH.md Week 1) need, and the Store description can say "Bring your snippets from Espanso, Beeftext or any spreadsheet". Core parsers with tests, no new package (hand-rolled YAML subset for Espanso's flat `matches` list). **Cost:** medium. **Needs copy:** the file-type labels and one failure message per format.
- [ ] **D19 Tray icon shows the paused state.** When Snippets are off, or the hook was refused (P12.6), the glyph is unchanged; only the tooltip says so. A dimmed glyph (Anvil at 50 %, or the white glyph with a small gap) tells the user at a glance. DESIGN §1 addition, `MarkRenderer` already renders the glyph at runtime. **Cost:** very low. **Needs copy:** none.
- [ ] **D20 A denser, more useful snippet list.** Each row shows chip and name; a second, secondary-text line with the first 60 characters of the body (variables shown as typed) helps a user with thirty snippets recognise one at a glance, and a "last used" sort (with the search box) puts the daily ones on top. The timestamp is metadata (`lastUsedUtc`), not text, and the privacy copy stays true; decide whether it belongs in `snippets.json` or only in memory for the session. **Cost:** low. **Needs copy:** the sort control.
- [ ] **D21 Type instead of paste, per snippet.** Some targets refuse Ctrl+V or have no clipboard (terminals, some remote-desktop clients, password fields a user deliberately wants a snippet in). A per-snippet "Type it out instead of pasting" switch sends the text with `KEYEVENTF_UNICODE` keystrokes; slower for long bodies, but it works where paste does not and never touches the clipboard. Espanso's "inject mode". **Cost:** low once D15's `TypeText` exists. **Needs copy:** one row.
- [ ] **D22 Fill-in fields** (`{field:Name}` asks for values in a small dialog before inserting) are already the named v1.1 Pro candidate (LAUNCH.md). Keep them after D14–D18: they are the one feature here that competitors sell, so they are the natural paid unlock, and the free tier's "no cap" promise stays intact.

### Performance (measure first; each task starts with a number)

- [ ] **P13.5 Startup time.** The DESIGN checklist asks for launch-to-tray under 1 s and nothing has measured it. Add a Stopwatch from `App()` to tray creation and from `ShowMainWindow` to the first `ContentRendered`, written to the event log as two durations (numbers, not text). Then try `PublishReadyToRun=true` in `pack-release.ps1` and `pack-msix.ps1`: WPF apps typically start 30–50 % faster with ReadyToRun; the download grows by roughly a quarter. Keep it only if the measured gain is real on the 4 GB laptop.
- [ ] **P13.6 Drop the WinForms dependency.** `Wordwright.Platform` uses `System.Windows.Forms` for two things: `Clipboard`/`DataObject` and `Screen.AllScreens`. That pulls about 25 MB of assemblies into the publish folder and initialises WinForms on the first expansion. The clipboard already goes through Win32 for writing; reading the whitelist formats via `OleGetClipboard`/`IDataObject` (or `GetClipboardData` for text, RTF, HTML, CSV and `CF_HDROP`) and monitors via `EnumDisplayMonitors` removes the dependency. Measure publish size, idle working set and first-expansion latency before and after.
- [ ] **P13.7 Page cache.** WPF-UI rebuilds a page on every navigation, so Settings re-reads the library and the Snippets page re-runs `Reload` each visit. If `NavigationView`'s page cache (`NavigationCacheMode`) keeps the three pages alive, navigation becomes instant and the `Expanded`/`FlushingEdits` subscriptions stop being re-wired. Measure navigation time first; skip if it is already under 50 ms.
- [ ] **P13.8 Idle footprint.** Record idle working set and private bytes after ten minutes in the tray (expect 60–90 MB for WPF; WinForms adds more, see P13.6). Add a one-line target to the DESIGN checklist so it is checked each release.
